# 大模型（LLM）总结功能

> 本文记录大模型 AI 总结功能的设计与实现，包括手机端配置接口、手表端存储架构，以及连通性检测页面。

---

## 1. 功能概述

手表端通过局域网 HTTP 与手机端通信，手机端向手表端写入大模型配置（服务商、API Key、模型、Prompt 等）。配置完成后，手表端在阅读 RSS 文章时可调用大模型接口生成摘要。

**主要组成：**
- 手机端配置接口（`/getLLMSummaryConfig`、`/setLLMSummaryConfig`）
- Ability 注册（手机端识别并跳转配置页）
- 手表端存储（DataStore + EncryptedSharedPreferences）
- 连通性检测页面（Settings → AI 连通性）

---

## 2. Ability 注册

`GET /getCurrentActivationAbility` 在 LLM 配置服务器模式下返回：

```json
{
  "code": "a3e72c1d-5f84-4b90-9d16-e8c047f2b3a1",
  "name": "LLM总结配置",
  "version": "0.0.1"
}
```

`code` 为固定 UUID，手机端硬编码匹配此值后跳转配置页。

**注册位置：**

| 文件 | 改动 |
|------|------|
| `PhoneConnectionAbility.kt` | 新增 `LLM_SUMMARY_CONFIG` 枚举，加入 `orderedValues` |
| `LocalHttpServer.kt` | 新增 `ServerType.LLM_CONFIG` 和 `createLlmConfigServer()` |

`CONNECTION_HUB` 服务器因 `orderedValues` 已包含 `LLM_SUMMARY_CONFIG`，自动支持新端点。

## 3. HTTP 接口

### 3.1 GET /getLLMSummaryConfig

手机端进入配置页时调用，回显已保存的配置。

**响应（已配置）：**
```json
{
  "success": true,
  "data": {
    "provider": "deepseek",
    "apiKey": "****abcd",
    "model": "deepseek-chat",
    "baseUrl": "",
    "systemPrompt": "请用简洁的中文对以下文章进行摘要，不超过80字。",
    "enabled": true
  }
}
```

**响应（尚未配置）：**
```json
{ "success": true, "data": null }
```

> `apiKey` 回传时脱敏：保留末 4 位，其余替换为 `****`。

### 3.2 POST /setLLMSummaryConfig

手机端保存配置时调用，请求体为 JSON：

```json
{
  "provider": "deepseek",
  "apiKey": "sk-xxxxxxxx",
  "model": "deepseek-chat",
  "baseUrl": "",
  "systemPrompt": "",
  "enabled": true
}
```

校验规则：`provider` 和 `apiKey` 不能为空，否则返回 `{ "success": false, "message": "..." }`。

## 4. Provider 枚举

| provider 值 | 显示名称 | 手表侧默认 Base URL |
|-------------|---------|-------------------|
| `openai` | OpenAI (ChatGPT) | `https://api.openai.com/v1` |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` |
| `qwen` | 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `zhipu` | 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` |
| `custom` | 自定义 | 由 `baseUrl` 字段指定 |

所有服务商均使用 OpenAI Chat Completions 兼容格式（`POST /chat/completions`）。

`model` 为空时各服务商的默认模型：`openai` → `gpt-4o-mini`，`deepseek` → `deepseek-chat`，`qwen` → `qwen-turbo`，`zhipu` → `glm-4-flash`。

## 5. 存储架构

配置分两部分存储：

### 5.1 非敏感字段 — DataStore（`settings.preferences_pb`）

| DataStore Key | 类型 | 说明 |
|---|---|---|
| `llm_provider` | String | 服务商枚举值 |
| `llm_model` | String | 模型名称，空串表示使用默认 |
| `llm_base_url` | String | 自定义 Base URL，非 custom 时为空串 |
| `llm_system_prompt` | String | 总结 Prompt，空串表示使用内置默认 |
| `llm_enabled` | Boolean | 是否启用 AI 总结 |

入口：`SettingsRepository.llmProvider / llmModel / llmBaseUrl / llmSystemPrompt / llmEnabled`，批量写入方法 `setLlmConfig(...)`。

### 5.2 API Key — EncryptedSharedPreferences（`llm_secure_prefs`）

使用 `androidx.security:security-crypto:1.1.0-alpha06`，Android Keystore AES256-GCM 主密钥，SharedPreferences Key/Value 分别以 AES256-SIV / AES256-GCM 加密。

入口：`LlmApiKeyStore`（`app/src/main/java/.../data/settings/LlmApiKeyStore.kt`）

```kotlin
llmApiKeyStore.getApiKey()   // 读取明文 key
llmApiKeyStore.setApiKey(key) // 写入并加密
llmApiKeyStore.hasApiKey()   // 是否已配置
```

`LlmApiKeyStore` 通过 `AppContainer.llmApiKeyStore` 注入到 `LocalHttpServer` 和 `LlmConnectivityViewModel`。

## 6. 连通性检测页面

**入口：** 设置 → AI 连通性（`MainSettingsPage` 中"高级"下方的新增条目）

**路由：** `llm_connectivity`（`AppNavGraph.kt`）

**ViewModel：** `LlmConnectivityViewModel`

测试流程：
1. 读取当前 provider / model / apiKey
2. 解析 Base URL（自定义时使用 `baseUrl` 字段，其余使用硬编码官方地址）
3. 发起 `POST {baseUrl}/chat/completions`，payload 为 `max_tokens=16`、消息内容 `"Hi"`
4. 成功：展示延迟毫秒数和模型回复片段（最多 40 字符）
5. 失败：展示错误原因（HTTP 错误码、网络异常、`error.message`）

**UI 状态机：**
```
Idle → Testing → Success(latencyMs, replySnippet)
                → Failure(message)
```

未配置 provider 或 API Key 时，按钮禁用，页面提示配置引导。
