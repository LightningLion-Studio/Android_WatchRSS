# Compose 1.3.3-5 发布审查

## 基线与范围

基线为 `v1.3.3-4`。
本次修复抖音画面闪烁、卡在首帧、一直加载，以及视频没有声音的问题，不含其他改动。

## 原因

1. 从桌面再次打开应用时，首页压在已停止的抖音页面之上。再次进入抖音会新建第二个抖音页面。两个页面共用同一组播放器，每约 0.45 秒互相重新绑定，表现为闪烁、卡首帧、黑屏转圈。
2. 抖音 feed 的 `bit_rate` 同时含 `format=mp4`（音视频合流）和 `format=dash`（仅视频，音频在 `bit_rate_audio`）。DASH 码率最低，选择器总选中它，所以视频没有声音。

## 修复

1. `DouyinEntryActivity`：每个抖音页面使用独立的播放器池；新页面创建时关闭旧页面。
2. `DouyinImmersiveScreen`：只有最新的抖音页面在退出时保存并清空共享预览缓存，被替换的旧页面不会清掉新页面正在用的缓存。
3. `DouyinUnifiedParser`：丢弃 `format=dash` 的码率项。
4. `DouyinPlaybackSelector`：排除路径含 `/media-video-` 的地址，覆盖已持久化的旧缓存项。

## 行为变化

合流 MP4 码率高于 DASH 视频流，每条视频流量略增，起播可能略慢。

## 验证边界

- Release 单元测试：825 项通过，0 失败、0 错误、0 跳过。新增 1 项选择器测试。
- 同源码独立 Compose 包在 OWW242 上验证：
  - 按“播放中按 Home → 从桌面打开 → 再进抖音”复现 3 次：旧页面约 0.3 秒内关闭，播放器只剩一组，无重新绑定循环，截图有画面。
  - 修复前同一步骤复现出每约 0.45 秒一次的重新绑定循环。
  - 刷 4 条视频，播放器均识别并选中 AAC 音轨，系统出现本应用的播放中 AudioTrack；用户确认有声音。
- 正式包名 APK 未在设备上覆盖安装。
- 播放中偶发约 20 秒缓冲（带宽估计远低于码率）未处理。
- 连续长时间观看、断网、弱 Wi-Fi 未测试。
